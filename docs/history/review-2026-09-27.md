# Code and feature review, 2026-09-27

> **A snapshot, not a standing document.** Taken at `06b237f` (2026-09-26),
> after WT350 and WT351 were sent. Line numbers refer to that commit and will
> drift. Treat it as a work list: when a finding is fixed, say so in the
> commit and strike it here, or delete the file once it is empty.

## Summary

The codebase is in better shape than its speed suggests. The load-bearing
choices hold up under adversarial reading:

- one JSON document per issue;
- `plan.ts` as the one planner, so the editions cannot drift;
- `savedFresh`;
- compare-and-set write-back;
- a revision on every save;
- verify-after-send.

The security basics are clean. Every `spawn`/`execFile` takes an argument
array, SQL is parameterized, static serving has no path traversal, no secret
reaches the client bundle, and the public share page renders only the
filtered website edition with notes escaped.

The defects cluster in four places:

1. **The page-open sweep races write-back.** A re-scan can revert an edit Jamie
   has just written to Pinboard or Micro.blog. `savedFresh` protects the
   document from a stale *copy*. It does not protect against a stale *remote*
   being reconciled against a merge base that moved.
2. **Send state is replaced, not accumulated.** A failed or interrupted leg
   erases the last good record: the podcast's audio reference, Buttondown's
   draft id. That blocks re-sends and can create a second Buttondown draft.
3. **The client editors fight the server copy.** Three ways typing is lost:
   - RichEditable shows the old text for the whole save round trip, and can
     save it back over the edit.
   - Inspector fields are controlled by the saved value and reset on any
     re-render.
   - Ad hoc headings are editable, but the edit is never saved.
4. **The edge of the app.** Every POST route accepts a cross-site "simple"
   request with a `text/plain` body, and that includes
   `send/website?force=1`. There is no Host allow-list against DNS rebinding
   on the loopback port, and a malformed Host header kills the process.

Beyond those four, one data-loss path is cheap to close. Creating an issue at
a number another issue was renumbered away from overwrites that issue, even a
published and put-to-bed one.

## 1. Fix first

### 1.1 Creating an issue can overwrite a renumbered one (high, S)

**Mechanism**

- `createIssue` fixes the id as `wt${number}` (`src/server/issue.ts:115`).
- `setIssueNumber` changes only the number (`issue.ts:1031`).
- `POST /api/issues` checks collisions by number alone
  (`src/server/index.ts:387`).
- `saveIssue` is an upsert, `INSERT … ON CONFLICT(id) DO UPDATE`
  (`src/server/db.ts:207`).

**Reproduced over HTTP**

1. Create 353 by mistake, fix it to 352 in Settings, send it, put it to bed.
2. Next week the index offers 353. `POST /api/issues` returns 200.
3. The published WT352 row is replaced by a blank draft: its document, send
   evidence, status and bed state.
4. The only copy left is one revision, and it is trimmed after 300 saves.

The SetupSheet tells Jamie "nothing is discarded". The same collision
overwrites a renumbered *draft* in progress.

**Fix**

- An insert-only `createIssueRow` in `db.ts`, so an id conflict throws and
  becomes a 409.
- At minimum, also refuse when `store.getIssue('wt' + number)` exists.
- Routes test: create 353, renumber it to 352, create 353, expect 409.

### 1.2 A re-scan reverts an edit that was written back while it ran (high, S)

Three reviewers found this independently.

**Mechanism**

- `fetchForSweep` reads the Micro.blog index first, then Pinboard one
  bookmark at a time (`issue.ts:192–217`). That takes 10–20 s.
- The page-open scan runs while Jamie edits (`src/client/components/Editor.tsx:214`).
- A write-back that lands meanwhile moves `source_snapshot`
  (`index.ts:174–183`).
- At apply time `reconcileItem` sees theirs (stale) ≠ base (new) with
  local = base. It adopts the stale remote and logs "adopted the Pinboard
  edit" (`src/server/reconcile.ts:88–92`).

**Consequences**

- The old words are back until the next scan, and a send in between ships
  them.
- A Notable→Briefly move reverts *permanently*: `followBookmarkTags` follows
  the stale `_brief` tag, and afterwards the bookmark carries no section tag
  to follow back.
- Jamie's next edit hits compare-and-set and lands in `conflict`, which has
  no way out (below).

**Fix**

- `SweepFetch` records each item's `source_snapshot` and `sync_state` at
  fetch time.
- `applySweep` skips reconcile and tag-following for any item whose snapshot
  has moved since, or that is `syncing`. The next scan reconciles it
  correctly.
- Add a regression test beside the fresh-read test in `tests/issue.test.ts`.
  That test covers only an unmoved snapshot, which is why this race was
  missed.

**Follow-on (medium): `conflict` needs a way out**

Today a re-scan keeps it, write-back refuses it, and the error text says
"re-scan". Add:

- **Keep mine**: move the snapshot to the current remote, then write.
- **Take theirs**: adopt the remote fields and snapshot.
- A readiness `sync` unit for items in `conflict`.
- New error text that does not send Jamie to a re-scan.

### 1.3 YAML front matter breaks on ordinary link titles (high, S)

**Mechanism**

- `yamlScalar` (`src/server/publish.ts:228`) quotes a value only when it
  starts with a digit, `-`, `+` or `.`, or contains `:` or `#`.
- `url`, `domain` and `section` are written without it.

**What breaks** (checked against js-yaml 3, which gray-matter and so Eleventy
use)

- An arXiv bookmark, `[2410.12345] Scaling laws for agents`.
- A title starting with `"`, `@`, `*`, `` ` ``, `!`, `|` or `{`.
- A dek that opens with a quote.
- `&copy; and trademarks` parses silently as `and trademarks`.

**Impact**

- The site build fails, so the issue page never deploys.
- Every later site deploy also fails until someone hand-fixes the page in the
  site repo.
- The archive leg commits the same front matter.

**Fix**

- Emit every string scalar as `JSON.stringify(value)`. A JSON string is a
  valid YAML double-quoted scalar.
- If uniform quoting makes too much re-send diff noise, leave a value bare
  only when it matches a conservative safe pattern.
- Teach `backfill.ts`'s front-matter reader to JSON-unescape.
- Add a table-driven round-trip test through js-yaml (a devDependency) for
  each indicator character.
- Expect `fixtures/expected/` to change; say why in the commit.

### 1.4 The canvas and the Inspector lose typing (high, S–M)

**RichEditable** (`src/client/components/Row.tsx:531–546`)

The problem:

- On blur it re-renders from the *old* `value` until the PATCH returns. For a
  mirrored field that includes the awaited Pinboard or Micro.blog write,
  0.5–3 s.
- Clicking back in during that window edits the old text, and the next blur
  saves it over the edit and writes it back.
- A transport failure (the service restarting under `npm run deploy`
  mid-session) leaves the typed text gone from the screen.

The fix:

- Keep a `pendingRef` and render `pending ?? value`, clearing it when the
  prop catches up.
- On failure, keep the pending text on screen, marked unsaved.
- In `call()`, fall back to the status text when an error body is not JSON.

**Inspector fields** (`src/client/components/Inspector.tsx:37–55`, and every
input)

The problem:

- Each field is `value={item.x}` with no local state.
- Any Editor re-render resets what is being typed: another save landing, or
  the sweep.
- The sweep's hold-until-blur checks only `isContentEditable`
  (`Editor.tsx:199`).

The fix:

- Make the fields uncontrolled while focused: `defaultValue`, and sync from
  props only when the field is not `document.activeElement`.
- Widen the sweep hold to `input, textarea`.

**Escape in an Inspector field** (low, `Editor.tsx:222`)

It closes the panel without committing, and Safari fires no blur.

**Tests**

A WebKit e2e test that holds a PATCH with `page.route` and asserts the text
survives, both while the save is pending and after it fails.

### 1.5 Ad hoc section headings are editable but never saved (high, S)

**Mechanism**

- `src/client/components/Page.tsx:296–302` makes the heading editable for
  `ad_hoc` and `promoted_item` nodes.
- Its `onCommit` is a no-op commented "renamed from the outline". The outline
  has no rename.
- `api.renameNode` and the `/rename` route exist, and `git log -S` shows the
  client has never called them.
- The website, the email and the audio all publish `## Section`.

**Fix**

- Wire `renameNode` for `ad_hoc`.
- For `promoted_item`, commit the edit as the item's title. That is what the
  renderer prints, and it writes back to Micro.blog.
- Add an e2e test.
- Update `docs/status.md` in the same commit: a route coming into use is a
  contract.

### 1.6 The edge: CSRF, DNS rebinding, and a crashable Host parse (high/medium, S)

**CSRF (high)**

- The dispatcher matches method and path only (`index.ts:1257`).
- `readBody` JSON-parses whatever the Content-Type (`index.ts:86`).
- So every POST is a CORS-simple request. A page open in Safari can POST a
  `text/plain` body to the tailnet URL, which is printed in the public README.
- Verified against an offline server with `Origin: https://evil.example`:
  - `/settings` saved an attacker's title.
  - `/send/website?force=1` got past the podcast gate, and failed only on the
    missing offline token. In production that request is a commit to the live
    site.
- DELETE and PATCH need a preflight, which gets a 404, so they are safe.

**DNS rebinding (medium)**

- There is no Host allow-list.
- A rebinding page that reaches `127.0.0.1:4317` from a browser on otto can
  use any method, including `DELETE /api/issues/:id`.
- The tailnet HTTPS endpoint cannot be rebound (TLS name mismatch).

**Crash (medium)**

- `new URL(req.url, 'http://' + host)` sits outside the `try` block
  (`index.ts:1258`), so `Host: a b` kills the process.
- During a send, that strands the leg in `sending` for ten minutes.

**Fix: one guard beside `guardBed`**

```ts
// Before routing, for every method except GET and HEAD.
const site = req.headers['sec-fetch-site'];
if (site && site !== 'same-origin' && site !== 'none') {
  throw new HttpError(403, 'cross-site request refused');
}
const origin = req.headers.origin;
if (origin && !ALLOWED_ORIGINS.has(origin)) {
  throw new HttpError(403, `requests from ${origin} are refused`);
}
```

- Add a Host allow-list that answers 421: `localhost:4317`,
  `127.0.0.1:4317`, the tailnet name, and the Vite proxy (which sets
  `changeOrigin`).
- Parse the URL inside the `try`, against a fixed base.
- The `scripts/` tools send no `Sec-Fetch-Site` or `Origin` header, so the
  guard does not affect them.

**Also: `DELETE /api/issues/:id`**

- The client never calls it, and it has no status guard.
- It drops the document without a revision and erases the event log.
- Remove it, or make it refuse anything that is not a draft.

### 1.7 Make `npm test` hermetic before adding the tests above (medium, S)

**The unit suite reads the real `.env`**

- vitest has no environment override.
- `tests/routes.test.ts` imports the whole server.
- `src/server/config.ts` loads the real `.env` (write-back on, every key
  present) whenever `WT_BUILDER_OFFLINE` is unset. That is every
  `npm run deploy` on otto.
- Today every route test fails before reaching the network because each was
  written with care, not because anything prevents it.
- The tests this review asks for would reach live Pinboard and GitHub on the
  Mac while passing harmlessly in CI: write-back, moving a swept link, the
  send legs.
- Fix: `test: { env: { WT_BUILDER_OFFLINE: '1' } }` in `vite.config.ts` (or a
  setup file). Tests that need a service stub `fetch` explicitly.

**`npm run test:e2e` builds into the `dist/` the live service serves**

- An untested client can reach Jamie mid-session, before `npm test` has run.
- Fix: a `WT_BUILDER_DIST` environment variable, and
  `vite build --outDir tmp/e2e/dist --emptyOutDir` for the browser suite.

## 2. The send path (medium)

### 2.1 A failed leg erases the last good send record

Six findings share one root: `recordSend` replaces a leg's whole `SendState`
(`db.ts:258`).

**Podcast**

1. A podcast re-render fails, and the leg becomes `{status: 'failed'}` with
   no `audio`.
2. Website re-sends now 409 with "the podcast leg has not run".
3. "Re-send all sent" stops at that first leg.
4. The error's own escape, `?force=1`, commits a page and an `emails.json`
   entry *without* `audio_url`. The episode drops off the page and out of the
   feed.

**Buttondown**

- `sending` drops `external_id`.
- The in-flight guard runs before the rehost await (`index.ts:995–1008`).
- So a restart mid-PATCH, or two concurrent clicks, creates a second draft.
  Schedule the wrong one and readers get two emails.

**Fix** (also feature #1 below)

- `recordSend` carries a `last_sent` through `sending` and `failed`. That one
  place covers all four legs.
- Read the draft id and the audio from `last_sent` as a fallback.
- Gate the website on "an audio reference is recorded", not on
  `status === 'sent'`.
- Record `sending` synchronously, straight after the guard.
- On boot, mark every persisted `sending` as `failed: interrupted by
  restart`. Sends run in-process, so any `sending` found at boot is stranded.

### 2.2 The first website send hotlinks new images

- `sendWebsite` saves the rehost map to a fresh read, but renders from the
  copy it read *before* the rehost (`index.ts:1104–1110`).
- Every new Journal photo ships as the Micro.blog original until a later
  re-send.
- One-line fix, mirroring the Buttondown leg: render
  `savedFresh(id, d => applyRehost(d, mapping)).issue`.
- Add a warn-level "no hotlinks" check to `verifyWebsite`.

### 2.3 Website verify judges the old deploy on a re-send

**Mechanism**

The deploy wait ends when the page answers 200 and carries the title
(`src/server/verify.ts:175`). The previous build already does both.

**Consequences**

- After "podcast re-run, then website re-send", verify fails with "re-send
  the website": it tells Jamie to do what he just did.
- A text fix whose site build then fails in CI reports *passed*.

**Fix**

- Count the page as landed only when it also carries this send's audio
  filename (when audio is recorded). Better: poll the commit's check runs.
- Past the deadline, return `waiting` with a recheck rather than `problems`.

### 2.4 Send view safety

- **A double-click on Publish lands on "Send the rest"**
  (`Editor.tsx:335` → `Send.tsx:258`).
  - One gesture runs the website commit, the Buttondown draft and the archive
    commit.
  - Fix: a `confirm()` naming the legs on all three bulk buttons.
  - Also check a cancelled ref between legs, so "← Issue" stops the chain.
- **A failed send never shows DID NOT SEND.** The card keeps its pre-send
  state. On a re-send it stays a green SENT with the old VERIFIED panel.
  - Fix: re-read the issue in `send()`'s catch.
- **In-flight state lives in the component.** Leave the view and come back,
  and a sending leg looks unsent and clickable.
  - Fix: treat `doc.sends[leg].status === 'sending'` as running, and poll
    while any leg is.
- **A late response for another issue replaces the one on screen**
  (`src/client/app.tsx:18–22`), then restarts that issue's sweep in a loop.
  `posts/all` is limited to once per five minutes.
  - Fix: drop any response whose issue id is not the route's.
  - Put `key={doc.issue.id}` on Editor and Send.
- **Send unmounts the Editor.** Every trip to Send and back re-sweeps and
  loses the review triage.
  - Fix: render Send over a mounted Editor. `.send-layer` is already fixed
    position.
- **No browser test opens the Send view.** Offline mode makes every case
  above deterministic. Add `tests/e2e/send.e2e.ts`.

### 2.5 Fixing a published issue

**Number, date and window still save on a published issue**

- Each saves at once, and the next "Re-send all sent" publishes a different
  edition.
- A renumber forks everything:
  - the site page;
  - `emails.json`;
  - the feed (a second episode guid for the same mp3, so subscribers download
    it twice);
  - the archive.
- Fix: `/settings` refuses number, date and window when the status is not
  draft. `/sweep` refuses on non-drafts, which the client already assumes.

**The canvas locks as soon as Buttondown's *draft* exists**

- `published` is derived once the website and Buttondown legs are both
  `sent`, which happens before Jamie has reviewed the draft.
- Title and dek (the email subject) then have no edit path.
- A fix made in Buttondown is reverted by the next re-send.
- Feature #4 below keeps text editable until the issue is put to bed. It
  changes the spec (`docs/interface-spec.md:484`), so it is Jamie's call.
- The minimum: Title and Dek in the MetaEditor.

**Two related gaps, both in the feature list**

- Nothing shows which legs have changed since they were sent (feature #11).
- Re-sending Buttondown after the email has gone out PATCHes the delivered
  email's web copy (feature #7).

## 3. Content correctness (medium unless marked)

- **HTML in a link title becomes markup** (`src/shared/render/website.ts:101`,
  `:108`, `:140`, `:204`).
  - "Styling the `<textarea>` element" turns the rest of the issue into a text
    box, on the site and in the email.
  - Fix: escape external fields only (title, media alt, media location):
    Markdown link metacharacters plus `<` and `>`. Never Jamie's commentary or
    body.
- **The Journal lead welds structure** (`website.ts:130–141`).
  - A post that opens with a quote, a list, or a lead-in line followed by a
    list comes out as "10:54 AM — > quote".
  - A `##` heading inside a post collides with the day headings.
  - The same class as the WT351 fix, in a different shape.
  - Fix: weld only plain prose, and demote post headings to h4.
- **A new issue created on a Saturday gets the previous issue's date and
  window** (`src/client/components/Index.tsx:388`, `src/shared/dates.ts:158`).
  - This is exactly what following the OmniFocus task on send day does.
  - The sweep fills WT352 with last week's links, and holding them out writes
    `_exclude` onto bookmarks WT351 published.
  - Fix: default to the Saturday after the latest issue's date, and refuse a
    date another issue already holds.
- **Micro.blog drafts (not confirmed against the live service).** The sweep
  never reads `post-status` (`src/server/integrations/microblog.ts:24–31`).
  - If `q=source` returns drafts, a draft goes to every reader.
  - A one-line guard either way. Check once against the real account.
- **Low:**
  - The Micro.blog sweep stops at the newest 100 posts.
  - Liquid `{{ }}` and `{% %}` in content reach Buttondown's template engine.
  - Quote items are spoken as Jamie's own words, with no "Quote … End quote".
  - WebVTT cues do not escape `<` or `&`.
  - With the 14- and 21-day windows the UI offers, Journal day headings repeat
    a weekday.

## 4. The issue model (medium)

- **Restoring a removed section brings back only its original items.**
  - Links swept in while it was removed stay in `orphans`: in no edition, on
    no screen (`src/server/issue.ts:504–517`).
- **Orphans have no Put back.**
  - `docs/decisions.md` names "Held out / Put back" as what makes no-undo
    tolerable, and it was never built.
  - So the X on a Journal post or a promoted heading cannot be undone in the
    app.
  - This is a gap in a documented route, not a documented absence.
  - Fix: build the Held-out strip, and `POST /items/:id/putback`.
- **Promoting twice** (a double-click, or two tabs) creates two nodes with
  one id, and the post vanishes from every edition (`issue.ts:675`).
  - Fix: make promote idempotent.
- **Overlapping write-backs on one item** can mark the newer edit `synced`
  with the older outcome.
  - Fix: serialize `writeItemToSource` per item, and set `synced` only when
    the fresh item still equals what was written.
- **Low:**
  - Every sweep re-sorts the Journal by date, undoing the Up/Down moves the
    rail offers.
  - If the compare-and-set read fails, write-back writes blind with the last
    scan's flags. The defaults are private and unread, so this is not a
    privacy leak.

## 5. Editorial and LLM (medium unless marked)

- **Echo citations are never checked** against what the Librarian returned
  (`src/server/editorial.ts:1183`, `:1226`).
  - An invented WT number, or a label that disagrees with its
    `/archive/n/` URL, reaches readers under Thingy's byline.
  - Fix: `echoGrounding()` flags ungrounded citations in the picker and never
    drops anything (generation offers). Cover the per-echo redraft too.
- **Thingy's words are fed back as Jamie's archive.**
  - The archive leg commits the website render, Thingy's frames included.
  - Librarian passages carry no author.
  - `linkGrounding` labels what it retrieves "What Jamie has written about
    this subject before".
  - Fix: filter Thingy's sentences out of retrieved passages now, and add an
    `author` field in librarian-thing later (feature #9).
- **PROOF notes on the caption, alt, place or Ask question are pruned before
  display** (`editorial.ts:174–188` against `Editor.tsx:239`).
  - Two copies of "anchor text" have drifted, so the typo ships and is spoken.
  - Fix: one shared `anchorText(item)`.
- **Truncation with thinking on** surfaces as an opaque `JSON.parse` error,
  at six call sites.
  - Fix: one `callJson()` helper that reports `max_tokens` and `refusal`
    readably, with caps raised to 8–16k.
- **Low:**
  - The Membership prompt hard-codes $48 and forbids one-time gifts, while
    the facts it is given say otherwise. That is reader-facing money copy.
  - The link wand's page text goes into the prompt unfenced, the fetch
    follows redirects to any host, and the read has no size cap. Fence it
    and cap it.
  - The seasonal excerpt includes held-out items.
  - `stripSignOff` misses Markdown variants.
  - Journal alts are mapped to pictures by position, with no count check.

## 6. The recovery net

- **Revisions hold about 150 edits, not 300.**
  - The limit is 300 per issue (`db.ts:98`), but each write-back adds a
    second revision with no new words, and trimming ignores time.
  - Fix: trim by count *and* age (keep 14 days, say), or skip the revision
    for a bookkeeping-only save.
- **`recordSend` overwrites the last `sent` record with no preimage.** 2.1
  fixes this.
- **`npm run revisions` compares only title, commentary and body.** Most of
  the confirmed losses print nothing: send records, nodes, settings.
- **There is no consistent database snapshot in the repo** (feature #12).
  - `db.backup()` is safe under WAL; follow it with
    `PRAGMA integrity_check`, keep the last N, and run it nightly beside
    wt-backfill.
  - The external backup should copy the snapshot, never the live db/-wal
    pair.

## 7. Tests, tooling, docs

**Test gaps on the riskiest paths**

- The Pinboard `posts/add` parameters. That is the private-bookmark failure
  that has already happened once, and a reversed flag spread still passes the
  suite.
- The `emails.json` refusal guards.
- The Send view.
- A published issue that is not yet put to bed.

**The `emails.json` floor is static**

It is fixed at 349 (`MIN_ARCHIVE_ENTRIES`) and weakens every week. Derive it
from the last published number.

**CI and `npm run deploy` skip the browser suite**

It is the only coverage of `guardBed` (423) and of the contenteditable
regressions. Add a Playwright job; Chromium and WebKit both run on
`ubuntu-latest`.

**`pixi.js` for confetti**

About 890 KB (256 KB gzipped) of WebGL for about 100 rectangles. A 2D canvas
does it in about 60 lines. After a deploy, open tabs 404 on its lazy chunk.

**Stale docs**

The docs test catches dead paths, not dead prose:

- **`README.md` is behind the facts.** It still says:
  - "Nothing has been sent to a reader yet";
  - Pinboard "reads the unread queue (`toread=yes`)";
  - website and podcast are "Built, never run".
- **`docs/integrations.md`** still describes write-back marking bookmarks
  read.
- **Last-writer-wins.** Nine documents and three code comments still say it.
  The code does compare-and-set.
- **`docs/interface-spec.md` and `docs/publishing-lifecycle.md`** still
  describe:
  - website send order as unenforced (the server now refuses a website send
    until the podcast has run);
  - a Thingy "mark reviewed" gate.
- **`docs/decisions.md`** calls text edits "a known hole". That predates the
  revisions table.

**Scripts that write to live services**

They default to writing and ignore unknown flags (`scripts/backfill-daily.ts`,
`buttondown:push`). Reject unknown flags, so a mistyped `--dry` cannot write.
