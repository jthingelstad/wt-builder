# Target workflow

## 1. Open the current issue

WT Builder always opens one issue. The main canvas shows included content in
reading order. A source tray shows unplaced or excluded Pinboard and Micro.blog
items.

## 2. Assemble items

Jamie can:

- create direct-content items,
- add imported candidates,
- edit Pinboard commentary before or after inclusion,
- classify and move links,
- exclude individual posts without deleting them,
- manually order items within a section, and
- promote or demote titled Journal posts.

## 3. Complete assisted content

- Haiku is generated from the assembled issue and selected or edited by Jamie.
- Membership is drafted in Thingy's voice using current campaign facts.
- Echoes is generated last by Thingy using the assembled issue and archive.

Thingy content is visibly attributed in the editor and in published outputs.

## 4. Preview editions

Website, Buttondown, and Audio previews are generated from the same canonical
items. Each preview identifies omitted or invalid items. Changing an item
updates all applicable previews.

## 5. Publish

Publishing is a later phase. The intended sequence is:

1. validate all edition contracts,
2. render and approve the audio script,
3. render/upload audio,
4. create or update the Buttondown draft,
5. produce the website archive handoff,
6. schedule or send in Buttondown,
7. verify the website and authoritative feeds.

The first prototype must not call production services.
